## Access, conservation and lifecycle

The common start gate re-resolves the current ownership record, live projection, loaded and supported unchanged footprint, property ownership and entry permission. It requires a current authenticated furniture user within five blocks with line of sight. Each running session rechecks the same state and authenticated connection nonce before each tick. Treatments affect only the user, require a living non-DOWNED player, and never target another player. Hose block changes additionally require ownership and entry permission for the full actual fire block; all ray chunks must already be loaded.

At most eight active utility sessions exist, with one per player. Supplies must be ordinary specified ingredients, not unrelated custom items. Planning checks the entire recipe before any inventory change, rejects ambiguous duplicate slots, and requires a single stack item for returned-vessel ingredients so it cannot overwrite a remainder. Consumed items and returned vessels are checkpointed with `Player.saveData()` before a delayed session starts. The synchronous Paper call offers no cross-file crash transaction acknowledgement; no crash-atomic guarantee is claimed. Output completion removes the session before inserting and saving one kit.

The only durable supply state is the ordinary player inventory and real cauldron contents. Sessions and tare are intentionally temporary, with no automatic resume, queued replay, offline processing or manufactured refund. Removal, suspension, authentication loss, DOWNED/death, range/LOS loss, permission loss and shutdown stop sessions. The autoclave cancels instead of granting an output after such a loss. Power and wheelchair helpers have separate state and controls.
